# 手机备份助手

**一句话**：双击一个图标 → 自动把手机里**新增的**照片按时间筛出来 → 镜像到硬盘对应文件夹 → 再同步到 123 云盘。全过程先给你看一张「从哪来、到哪去」的表，你确认才动手。

---

## 〇、先看：两个版本有什么区别

| 你手上的文件 | 需要装 Node.js 吗 | 说明 |
|---|---|---|
| **手机备份助手-完整版-免装Node.exe**（33 MB） | ❌ **不需要** | Node.js 已打包在里面，复制到任何 Windows 电脑双击就能用 |
| **手机备份助手-轻量版-需先装Node.exe**（240 KB） | ✅ **必须先装** | 体积小；电脑上要先装 [Node.js](https://nodejs.org)（下 LTS，一路下一步）；没装的话双击会弹中文提示告诉你去哪下载 |
| **源码包 / GitHub 仓库** | ✅ 需要 | 给会折腾或想改代码的人；解压后双击 `创建桌面快捷方式.cmd` |

> 发给别人：**只发"完整版"那一个文件**最省事，对方什么都不用装。
> 分辨方法：文件名带「免装Node」= 完整版；带「需先装Node」= 轻量版。

## 一、它解决什么问题

你原来的流程是：手机插电脑 → 一个一个文件夹对着看 → 手动往硬盘同名文件夹里拖 → 再传到 123 云盘。麻烦在**对比**，不在搬运。

这个工具把那一步自动化了：

- 自动扫手机指定目录，按**拍摄时间**判断哪些是新的（不是按拷贝时间）；
- 自动跳过硬盘上已经有的、状态库里记过的；
- 自动保持手机端的原始时间戳；
- 硬盘落盘成功后才去动云端，断网也不影响本地备份；
- 每次生成一份 HTML 报告，写明「这次新增了哪几张、跳过了哪些、为什么跳」。

## 二、用浏览器界面（推荐）

### 最快：双击桌面图标

装好之后桌面上会有一个 **「手机备份助手」** 图标（蓝色方块，里面是手机+文件夹）。
**双击它** → 后台服务静默启动（**不弹黑窗口**）→ 浏览器自动打开界面。

- 想要这个图标：双击目录里的 **`创建桌面快捷方式.cmd`**，会在桌面和开始菜单各建一个；
- 想关掉：网页右上角点 **「退出」**（会提示确认），服务停止，标签页可以关掉；
- 重复双击不会开第二个：已经在跑的话它只会把浏览器指过去；
- 给别人的时候：把整个文件夹拷给他 → 装 Node.js → 双击 `创建桌面快捷方式.cmd` → 双击桌面图标即可。

没有桌面图标也可以双击目录里的 `启动界面.cmd`（这个会留一个黑窗口，关掉即停止）。

**来源和目标都是任意选的**：来源可以是手机，也可以是任意一块硬盘上的某个文件夹（比如"旧硬盘 → 新硬盘"）；目标可以是任意盘、任意文件夹。

| 步骤 | 你做什么 | 界面给你什么 |
|---|---|---|
| **1 数据来源** | 选「📱 手机」或「💽 某块硬盘/文件夹」；选后者就填路径 | 顶部显示当前来源是否可用；来源下有哪些文件夹会在第 3 步列出 |
| **2 导到哪儿** | 下拉选盘（C/D/E/F/G…，带卷标和剩余空间），或直接填路径 | 列出该目录已有文件夹，点一下切过去；也能新建文件夹 |
| **3 分栏对应** | 点「扫描来源里有哪些文件夹」 | 来源按**大文件夹分栏**（DCIM / Pictures / 好图…，一栏一个卡片，并排显示），每栏里列出**小文件夹**：文件数 + 勾选框 + 目标下拉。默认目标**保留「大文件夹\小文件夹」结构**；目标已有同名文件夹的会自动打勾并显示「✓ 已有」+「目标已有 N 个 · 同名 M 个（X%）」，名字不同但内容重合的会显示「名字不同，但内容重合 N%」；每栏有「全选/全不选」，顶部有「全部按结构勾选 / 全部取消」 |
| **4 对比与勾选** | 可选填拍摄日期，选**文件类型**（照片 / 视频 / 文档 / 压缩包 / 全部，可多选），点「开始对比」 | 先给一张**对比表**：每个文件夹「来源 N / 目标已有 M / 新增 K / 体积」；下面按文件夹分组列出新增文件，可整组勾、也可逐条勾，每行还有 **👁 用系统看图打开** 和 **📁 在文件夹里定位** |
| **5 一次性执行** | 选「只导硬盘 / 硬盘+云盘 / 只传云盘」，点「开始执行」 | 只处理你勾的那些；进度条 + 日志；结束时生成"本次批次" |
| **6 导出** | 选批次 → 填目标文件夹 → 「导出」 | 把这一批新导入的文件**按原来的子文件夹结构**复制过去，**保留原始拍摄时间** |

要点：
- **先对比、后动手**：第 5 步之前不会往目标盘写任何东西；
- 文件夹对应**由你决定**，名字不一样也能手动选或采纳建议；
- 大文件夹（上万张）只列出前 200 行，勾选整组会连同其余一起处理，不会卡；
- 选过的来源/目标会记住；关掉那个黑色窗口 = 停止服务。

> 手机没插时界面顶部会标红，但**来源切到硬盘文件夹照样能用**（旧硬盘 → 新硬盘不需要手机）。

## 三、命令行（不想开浏览器时）

### 第 1 步：让电脑能读手机（一次性）

1. 手机：`设置 → 关于手机` → 连续点「版本号」7 次，开启开发者选项；
2. 手机：`设置 → 系统和更新 → 开发者选项` → 打开 **USB 调试**；
3. 数据线连电脑，手机弹窗点 **允许**（勾「一律允许」）。

验证：双击 `只看新增-不动文件.cmd`，开头会打印「手机 xxx（adb 已授权）」。如果提示「没有检测到手机」或「还没授权」，就是上面三步没做对。

### 第 2 步：首次设置（一次性）

双击 **`首次设置.cmd`**，按提示回答 5 个问题：

| 问题 | 建议 |
|---|---|
| 手机怎么连 | `1`（USB 调试 / adb） |
| 备份到硬盘哪个根目录 | `F:\heic格式照片` |
| 目录映射方案 | `A`（按手机原文件夹名分开） |
| 云端方式 | `T1`（123 客户端「备份盘」自动增量，免费） |
| 默认备份到哪里 | `2`（硬盘 + 云盘）；想只导硬盘就选 `1` |

结果写进 `config.local.json`（这个文件是你自己的，别删）。

### 第 3 步：先预演，再真跑

1. 双击 **`只看新增-不动文件.cmd`** → 只列清单，硬盘一个字节都不动；
2. 确认清单没问题 → 双击 **`一键备份.cmd`** → 看到表格后按回车执行。

## 四、映射表（方案 A，默认）

| 手机来源 | 硬盘落点 | 内容 |
|---|---|---|
| `/sdcard/DCIM/Camera` | `F:\heic格式照片\Camera\` | 相机拍的照片/视频 |

## 五、备份到哪里：三个开关

每次运行都能选，三种组合：

| 选择 | 双击/命令 | 会发生什么 |
|---|---|---|
| **只导硬盘** | `选择去向.cmd` 选 `1`，或 `一键备份.cmd --target disk` | 只往硬盘写，**完全不碰 123 云盘**（连 token 都不换） |
| **硬盘 + 云盘**（默认） | `2` / `--target both` | 先落盘，再上传/交管 |
| **只传云盘** | `3` / `--target cloud` | **不写硬盘**，直接从手机读到暂存区上传后删除 |

想固定下来：改 `config.local.json` 里的 `"run": { "target": "disk" }`，以后双击 `一键备份.cmd` 就按这个走。

⚠️ **只传云盘不能用 T1（备份盘）档位**——T1 的原理是"文件先落到硬盘，客户端再扫上去"，没有硬盘就没有云。要选 `3`，云端必须是 **T2 挂载盘** 或 **T3 开放平台 API**：

```bat
:: 只传云盘 + 挂载盘
一键备份.cmd --target cloud --cloud mount

:: 只传云盘 + 开放平台 API
一键备份.cmd --target cloud --cloud open123
```

程序会在第一次就拦住这种错误组合并告诉你怎么办，不会闷头跑一半。

还有一个细节：**记录是分开算的**。比如你昨天只导了硬盘，今天想补上云，用 `--target both` 跑一次，程序会发现"硬盘已有、云盘没有"，只补传云盘，不会把文件重拷一遍。

## 六、按时间区间备份（你提的核心需求）

```bat
:: 只要 2026-10-01 及之后拍的
一键备份.cmd --since 2026-10-01

:: 只要 2027 年整年拍的
一键备份.cmd --years 2027

:: 2026-10-01 到 2026-12-31 之间
一键备份.cmd --since 2026-10-01 --until 2027-01-01

:: 从上一次成功备份的时间点继续
一键备份.cmd --since-last

:: 只要 heic 文件
一键备份.cmd --name-glob "*.heic"
```

不想敲命令？双击 **`指定日期备份.cmd`**，它会问你「起始日期」「结束日期」。

**时间是按什么判断的**（重要）：

| 优先级 | 依据 | 说明 |
|---|---|---|
| 1 | 文件名里的 14 位时间 | `IMG20260901181943.heic` → 2026-09-01 18:19:43。**你的手机照片全靠这条，最准** |
| 2 | 文件名里的截图/微信格式 | `Screenshot_20261015_093012…`、`微信图片_20261020112233.jpg`、`mmexport<13位毫秒>` |
| 3 | 照片里的 EXIF 拍摄时间 | 其它 `.jpg`，读文件头，不需要额外软件 |
| 4 | 手机端的文件修改时间 | 都识别不出时才用，报告里会标成「不确定」 |

> 为什么不用电脑上的修改时间：你 `拍照` 里很多文件的修改时间是 2026-10-03（拷贝当天），拿它判断会把 2019 年的老照片当成新照片。程序读的是**手机端**的时间。

## 七、云端三档（默认免费）

123 云盘开放平台的 API **要花钱**（要买「开发者权益包」，内测还要求是会员），所以默认不走它：

| 档 | 做法 | 费用 | 精度 |
|---|---|---|---|
| **T1（默认）** | 123 客户端「备份盘」把硬盘落点目录自动增量上传 | 免费 | 目录级 |
| **T2** | 客户端把云盘挂成盘符（如 `Z:`），程序直接写进去 | 免费（需已开通挂载盘） | 单文件级 |
| **T3** | 开放平台 API（`clientID` + `clientSecret`） | 约 200 元/年（未证实） | 单文件级 + MD5 秒传 + 断网补传 |

### T1 怎么开（一次性，3 步）

1. 打开 123 云盘客户端 → **备份盘** → 新建备份；
2. 本地目录选 `F:\heic格式照片\Camera`（还有 `Screenshots`、`WeiXin`），云端目录选 `/手机备份`；
3. 保存。之后它自己增量上传，本地删除不影响云端。

⚠️ **别把整个 `F:\heic格式照片` 挂上去**——那 2051 张历史照片会一起吃掉云端配额（约 8–10 GB）。只挂三个落点目录。

### 切到 T2 / T3

```jsonc
// config.local.json
{
  "cloud": {
    "mode": "mount",                       // T2
    "mount": { "driveLetter": "Z:", "remoteRoot": "\\手机备份" }
  }
}
```
```jsonc
{
  "cloud": {
    "mode": "open123",                     // T3
    "open123": { "clientId": "你的ID", "clientSecretEnv": "PAN123_CLIENT_SECRET" }
  }
}
```
T3 的密钥建议放环境变量（不会明文躺在配置里）：
```bat
setx PAN123_CLIENT_SECRET "你的secret"
```

## 九、常见问题

| 现象 | 原因 / 解决 |
|---|---|
| 「没有检测到手机」 | USB 调试没开、线是充电线、或没在手机弹窗点「允许」 |
| 「手机已连接但还没授权」 | 解锁屏幕，重新插拔，弹窗里点允许 |
| 某个目录「没有文件」 | 目录不存在（不同手机路径不同），在 `config.local.json` 里改 `sources` |
| 微信/QQ 图片找不到 | Android 11+ 锁了 `Android/data`，adb 读不到。用手机文件管理器把图导出到 `Pictures/` |
| 云端没动静 | T1 需要客户端保持运行；首次要在客户端里手动建一次备份任务 |
| 想重来 | 删掉 `state\state.json`。注意：硬盘已有的文件仍会被「硬盘已存在」规则跳过，不会重复写 |
| 硬盘满了 | 程序在拷第一个字节前就会停下来告诉你差多少 |

**安全承诺**：不删除、不移动、不重命名任何已有文件；同名但内容不同的默认保留硬盘原文件并列入「冲突清单」；不做双向同步（云端删了不影响本地）。

```
跑测试.cmd
```
42 个自动化用例，覆盖：文件名时间解析、区间边界（含 since、不含 until）、目录映射、同名冲突、幂等、MD5、以及用假 123 服务器验证上传/秒传/分片。

最关键的一条断言：**10 张 2026-09 的照片 + 10 张 2027-03 的照片，`--since 2027-01-01` 时只应处理后者**。
